Reprovisioning with the Elastic IP, automatic first boot and SSM deploy
======================================================================

Transcribed from the operator session on 2026-10-11 (UTC). Times are UTC and
approximate to the minute. The AWS account ID is
replaced with <account-id>. Commands were run from the operator's workstation
(Windows PowerShell) in infra/terraform.

Goal: show that `terraform apply` followed by one workflow run is enough to
serve a commit, with no manual step on the server and no deploy target kept
in GitHub. Changes under test: #13 (versioned bootstrap, Elastic IP, deploy
targets in SSM Parameter Store) and #14 (parameter path fix).

2. Apply for #13: partial failure
---------------------------------

02:43  terraform apply tfplan

    aws_instance.web: Destruction complete after 31s
    aws_subnet.public_a: Modifications complete after 11s [id=subnet-09371c26c1c6910d3]
    aws_network_interface.web: Creation complete after 1s [id=eni-079ac2aac7772040a]
    aws_eip.web: Creation complete after 3s [id=eipalloc-0fe788047e8928318]
    aws_instance.web: Creation complete after 15s [id=i-077149aee34bdbb5c]

    Error: creating SSM Parameter (/aws-devops-infrastructure-lab/deploy/instance-id):
    operation error SSM: PutParameter, https response error StatusCode: 400,
    api error AccessDeniedException: No access to reserved parameter name:
    aws-devops-infrastructure-lab/deploy/instance-id.

    (the same error for public-host and release-bucket)

    terraform output instance_public_ip
    "77.113.3.55"

Cause: Parameter Store reserves names whose first segment starts with "aws"
or "ssm", and the project name starts with "aws". `terraform plan` does not
check this; only the API call during apply does. The network interface,
Elastic IP and new instance were already created, so only the three
parameters and the deploy policy update were missing.

Fixed in #14: the parameters moved to /deploy/<project_name>/.

Result
------

- `terraform apply` replaced the instance and the new one served the
  repository commit without any manual step on the server.
- The public address is now an Elastic IP held by a separately managed
  network interface, so later instance replacements keep 77.113.3.55.
- The deploy workflow found the instance, address and bucket in SSM
  Parameter Store; no deploy target is configured in GitHub.

Not covered here: the server evidence collector (nginx -t, listeners, TLS
handshake) has not been rerun on i-077149aee34bdbb5c yet; the records in
evidence/artifacts/terraform/ belong to the previous instance.
